# 依頼文

あなたはフロントエンド実装者として、次の SPEC に従い Web ToDo アプリを実装してください。外部 API は使わない。

## 要件（一行）

タスクの追加・完了切替・削除ができ、未完了件数を常に正しく表示する。タイトルは「ToDoアプリ」とする。

## 目的・シーン・スコープ

- ブラウザ単体・個人操作。
- やらないこと：ログイン共有、期限通知、並び替え、永続化（保存）

## データ定義

- タスク: `{ id, title, done, createdAt }`
- `id`：一意。表示順や配列 index を ID にしない
- `title`：必須（空/空白のみは不可）
- `done`：未完了=false、完了=true
- `createdAt`：作成日時（表示は任意だがデータに必ず持つ）

## ルール（操作の意味）

- 追加（正常）：新規タスクを1件足し `done=false` とする
- 完了切替：対象タスクの `done` を反転する
- 削除：対象タスクのみ除去する（取り違えない）
- 未完了件数：`done === false` の件数を、操作のたびに再計算して表示と一致させる（インクリメント頼みでズレないようにする）

## 状態遷移表（この表と矛盾しないこと）

| 操作 | tasks（一覧） | 未完了件数表示 | 入力欄/エラー |
| --- | --- | --- | --- |
| 追加（正常） | +1件（新規、`done=false`。一覧の一番下に追加） | 再計算で反映 | 入力クリア、エラー非表示 |
| 追加（エラー） | 変化なし | 変化なし | エラー表示（一覧は変えない） |
| 完了切替 | 対象のみ `done` 反転 | 再計算で反映 | 変化なし |
| 削除 | 対象のみ除去 | 再計算で反映 | 変化なし |

## 入力バリデーション

- 空・空白のみは追加不可。100 文字超は追加不可
- バリデーション NG のときは **一覧と未完了件数を変化させない**

## 受け入れ条件

本章の合否の**下限**は **P0** です。P0 で**一覧と未完了件数の一貫性**を掴み、P1 で **id による取り違え防止**と**入力拒否**、P2 で**複合操作と負荷**を確認します。

### P0（最小合格）

次の **3 件**をすべて満たすこと。ブラウザは AC-01 から。

- **AC-01** Given 一覧が空、When `買い物` を追加、Then 一覧が 1 件になり未完了件数が `1` になる
- **AC-02** Given `買い物` が未完了、When 完了切替、Then `買い物` が完了になり未完了件数が `0` になる
- **AC-03** Given `買い物` が完了、When 完了切替、Then `買い物` が未完了に戻り未完了件数が `1` になる

### P1（実務耐性：id とバリデーション）

次の **3 件**をすべて満たすこと。

- **AC-04** Given `A` と `B` がある（両方未完了）、When `A` を削除、Then `A` だけが消え `B` は残る（削除対象の取り違えがない）
- **AC-06** Given 入力が空白のみ、When 追加、Then エラー表示し一覧と未完了件数は変化しない
- **AC-07** Given 入力が 101 文字、When 追加、Then エラー表示し一覧と未完了件数は変化しない

### P2（完成度：連続操作と再計算）

次の **2 件**をすべて満たすこと。

- **AC-05** Given `A` が未完了、When `A` を完了にしてから削除、Then 未完了件数は常に正しく、削除後も矛盾しない
- **AC-08** 追加→切替→削除を連続で繰り返しても JavaScript エラーで止まらず、一覧の内容と未完了件数が常に整合している

## 出力の取り決め

- 生成物は `index.html` 1 ファイル
- `Tailwind CSS` を利用する
- 文言は SPEC のまま（言い換えない）。仕様外は追加しない
- `id` は配列 index を使わず一意に生成する（例：`crypto.randomUUID()`）
- 実装後、AC-01〜AC-08 を `AC-01: OK` / `NG` で記録する（NG は再現手順一言）。**P0 をすべて満たしてから P1・P2** を確認する
