# 第8章 requirements

## 要件（一行）

未ログインでは保護画面を表示しない。ログイン成功時のみ保護画面へ遷移でき、ログアウトで未ログインに戻る。

## 目的・シーン・スコープ

- シーン：ブラウザ単体・個人操作（手元のブラウザで試す想定）
- 目的：アクセス制御（直アクセス／ログアウト後戻る）を受け入れ条件で固定する練習
- やること：ログイン、ログアウト、保護画面のアクセス制御、失敗時表示
- やらないこと：本物の認証／認可、ユーザー登録、SNS ログイン、2FA、サーバ連携

## 状態（要件として固定）

- 状態は `未ログイン` / `ログイン中` の 2 つに固定する

## 資格情報と失敗表示

- ログイン成功の条件は次の固定値とする
  - メールアドレス: `demo@chapter8.local`
  - パスワード: `chapter8-demo`
- 固定値は画面に表示しない
- ログイン失敗時は定型文 `入力が正しくありません` を表示する（理由を細かく出しすぎない）
- 資格情報は**学習用に SPEC で固定**する。本番ではパスワード等を SPEC に直書きしないが、本章では AI 実装の再現性と動作確認のため requirements に書く

## 擬似セッション

- 擬似セッションは `sessionStorage` に `auth=1` のようなフラグで保持する（タブを閉じたら消える前提）

## 画面構成

- 画面は `index.html`（ログイン）と `protected.html`（保護画面）の 2 ファイル構成でよい
- 未ログインで `protected.html` を開いた場合は `index.html` に戻し、保護情報を表示しない
- ログアウト後は `sessionStorage` をクリアし、`index.html` に戻す
- ログアウト後にブラウザの戻る操作をしても、保護情報を再表示しない（`protected.html` の `<head>` 内チェックで対策）
