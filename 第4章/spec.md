# 依頼文

あなたはフロントエンド実装者として、次の SPEC と出力の取り決めに従い、Web メモアプリを実装してください。外部 API は使わないでください。

## 要件

- メモの作成・編集・削除ができ、再読み込み後も `localStorage` から内容を復元できる。
- 保存データが破損していても画面が壊れない。
- アプリのタイトルは「WEBメモアプリ」

## 目的・シーン・スコープ

- 目的：永続化と失敗時仕様を SPEC に書く練習
- シーン：ブラウザ単体・個人利用・オフライン前提
- やること：作成、編集、削除、保存、復元、バリデーション
- やらないこと：クラウド同期、共同編集、共有リンク

## データ定義

- メモ一覧（memos）: `Memo[]`（複数件を保持する）
- Memo: `{ id, title, body, updatedAt }`（`updatedAt` は ISO 8601 文字列など、仕様で1つに固定）
- `localStorage` の**保存キー名は固定**（実装で変えない。変更する場合は移行手順まで SPEC に書く）

## 永続化ルール

- 追加・編集・削除のたびに、一覧全体を JSON として保存する（都度保存）
- 初期表示時に読み込み、パース成功なら一覧を復元する

## 失敗時・エラー方針

- **JSON パース失敗**または**想定外の形**：**空の一覧**で起動し、画面上のメッセージで通知する（無言で失敗しない）
- **保存失敗**（`localStorage` が使えない環境など）が起きうるなら：画面は可能な限り維持し、ユーザーへ通知する（仕様で一言に固定）

## 入力バリデーション

- タイトル空欄は追加・保存不可（エラー表示）
- 本文の最大文字数を SPEC で固定（例：10,000 文字）。超過は拒否し、**一覧は変えない**

## 受け入れ条件

本章の合否の**下限**は **P0** です。P0 で**再読み込み・削除・空タイトル**を掴み、P1 で**破損データ**と**本文制限**、P2 で**`updatedAt` というメタ情報**が SPEC どおり更新されるかを見ます。

### P0（最小合格）

次の **3 件**をすべて満たすこと。ブラウザは AC-01 から。

- **AC-01** Given メモを 1 件保存済み、When ページを再読み込み、Then 同じ `title` と `body` が表示される
- **AC-03** Given メモを 1 件、When 削除、Then 一覧から消え、再読み込み後も復活しない
- **AC-05** Given タイトルが空、When 追加を試みる、Then エラー表示し、一覧と保存内容は変化しない

### P1（実務耐性：破損起動と本文拒否）

次の **3 件**をすべて満たすこと。

- **AC-04** Given 保存領域に**故意に壊した JSON** を入れる、When 起動、Then **一覧は空（または安全な初期状態）**で操作可能であり、**ユーザーへ通知**がある
- **AC-06** Given 本文が最大文字数を超える入力、When 追加または更新を試みる、Then 拒否し一覧は変化しない
- **AC-07** Given メモが 2 件ある、When 片方を削除、Then 削除したメモだけが消え、もう片方は残る

### P2（完成度：メタ情報の更新）

次の **1 件**を満たすこと。

- **AC-02** Given メモを 1 件表示中、When タイトルを編集して保存相当の操作、Then `updatedAt` が以前より新しくなる

## 出力の取り決め

- 生成物は `index.html` の **1 ファイル**にまとめる
- スタイリングには `Tailwind CSS` を利用する（CDN でよい）
- 保存キー名・フィールド名は SPEC のとおり。仕様外機能は追加しない
- 削除時に確認ダイアログは出さない
- 実装後、**AC-01〜AC-07** を `AC-01: OK` / `NG` でセルフチェックする（**番号順でなく** P0→P1→P2 の順で確認。NG は再現手順一言）
